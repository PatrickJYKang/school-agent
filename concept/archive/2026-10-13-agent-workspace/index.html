01 — Context that stays with the work

Your work, ready to continue.

A conversation sits beside its sources, files, and artifacts. Return tomorrow and continue from the same place.

  • A new working folder for every task
  • File uploads and connected source selection
  • Search across your authorized materials
  • Context references you can inspect and remove
02 — An agent that follows through

Research. Calculate. Create.

The agent can take several steps, inspect results, correct errors, and return something useful.

  • Web research with traceable sources
  • Code, calculations, and data analysis
  • Markdown drafts and separate graphics
  • Interactive explanations inside chat
  • Visible tool activity, stop, and steer controls
  • Parallel tasks across people and their agents
03 — Help with room for judgment

Set the kind of assistance.

Choose coaching, working together, or delegation within the institution’s rules. Educators can supply activity-specific guidance.

  • Coach: questions, hints, and feedback
  • Partner: make and revise together
  • Delegate: complete an agreed task
  • Review what AI contributed and what you decided
03 / Artifact collaboration

One task. One folder.
A shared place for the work.

Each new task gets its own folder. Casey asks their agent to analyse the samples. Jordan asks theirs to examine limitations. Ms. Chen’s agent prepares feedback. They work in parallel and contribute to the same shared files.

See who is doing what, follow progress, and inspect finished results. Each person directs their own agent in a separate conversation. Compatible updates appear in the folder together. When a decision is needed, the agent asks a clear question.

OneDrive is the default working location. Files save directly into a school-managed task folder. Share it with selected people who can view or edit. The institution retains control, and permission to manage sharing is separate from permission to edit files.

Working locations / Cloud first

Familiar files.
Simple sharing.

Default

OneDrive / SharePoint

A task folder in a school-controlled library. The backend creates folders and manages access under the institution’s policy. Administrators keep control when people leave.

Alternative

GitHub

A task folder in a school repository, with agent outputs and reviewed changes. Independent sharing needs a separate repository: access applies to the whole repository.

Advanced

Local folders

Available, with cloud encouraged for collaboration. Files remain on the device; GitHub integration can share a repository copy.

Reading a Word file does not create a draft by itself. When someone asks to edit it, Fieldwork brings the text into a Markdown draft in the task folder. The agent keeps any useful source context; people do not maintain document-to-source links. Reapplying revised text to a Word document is a later option. Word remains an accepted institutional format; the first release focuses on working drafts and agent assistance.

05 / An institution-provided product

The school sets the boundaries.
The person directs the work.

Institution controls for AI use

  • School sign-in and approved assistants or models
  • Connection and action permissions by group
  • Data handling, retention, and conversation visibility
  • Shared spending limits and individual allowances
  • Auditable external actions and an off switch

A restrained first release

  • One workspace for chat, tool activity, and artifacts
  • Research, code/data analysis, and artifact creation
  • Shared agent activity and finished results
  • Markdown drafts with light comments and revisions
  • Shared task folders in OneDrive or GitHub
  • Selected context from Canvas, Slack, and Outlook

Fieldwork’s scope is AI assistance and the artifacts it helps people make. Course management, messaging, email, and authoritative document storage remain in their existing systems. Open-source distribution lets institutions inspect and adapt the product.

Research and design lineage

The concept draws on Peninsula’s agent-accessible artifacts, Playlab’s educator-shaped tools, Flint’s chat and working surfaces, LibreChat’s scoped controls, and Goose’s action permissions. The proposed feature boundaries, Markdown drafts, connector defaults, product identity, copy, and layouts were designed for this brief. T3 Code’s isolated agent work informs coordination behind the scenes; the proposed shared activity interface is original. The chat visualization pattern also references official OpenAI visualization documentation. These are proposed capabilities, not a claim that a working product exists. The folder-sharing design also checks Microsoft’s sharing model and GitHub’s repository roles. Detailed decisions are recorded in the design reference log.
